# feature009 · 测试里写死监听端口 ⇒ 同机并发跑套件时互相 bind 失败（等排产归属，不等拍板）

登记时间：**09-27 00:5x**（`date` 现读，实测树 `HEAD=905c07b`）。

## 一句话

broker 侧那几个起真集群的用例把 NameServer / Broker 的监听端口写成了常量。单机单跑没事，
**同一台机上并跑两套套件就会 bind 失败**，而且失败形状是"整类一条没跑"而不是"某条断言红"——
读日志的人很容易把它当成代码回归，或者更糟：当成"环境抖动，忽略"。
这条已经真实咬过两次（见下面读数），修法是把端口换成 `freePort()`（本仓已有 4 个文件在用，是现成形状）。

端口写死与它没有直接因果链，我没有复现出"因为 bind 冲突 ⇒ 发送超时"。

## 后果为什么值得排产

1. **读数被污染**：`类级和 ≠ 模块汇总` 是"有类没跑起来"的 detector（归因尺就靠这条），
   而它的触发原因里有一条是"别人也在跑" ⇒ 收口时要把 6 条测试的缺失归因成环境，
   这本身就是一次人工判断，人工判断会错。
2. **同机串行是我的制度**（`全量测试必须同机串行`），但制度的代价是排队；把端口换成空闲端口之后
   同机并跑是安全的，制度可以放松一档。
3. 这条不属于任何"广告未兑现"，所以不会自己浮到台面上——修它没有任何功能收益，只是让测量干净。

## 归属建议

- 挂 **W4**（构建与测试面）：把这 5 个文件的 10+1 个写死端口换成 `freePort()`，
  并把 `HAServiceTest` 的 HA 端口（`31911` 附近那对）一起换掉——它现在是"主从两个监听 + NameServer"三段写死。
- 不需要拍板：换成空闲端口不改变任何被测语义（同一份代码，只是不跟邻居抢号）。
- 拍板要拍的只有一件事：**要不要顺便把"同机串行"这条纪律放松**（改完之后并跑理论上安全）。
  建议先改端口、再单独观察一轮 250 并跑的读数，别一次改两样。

## ⚠ 但 `freePort()` 本身也会红：09-27 01:1x 本机 12 轮全套里量到一次

同一轮测量里（`~/.cache/zmq_waves/dlqfix_local_r10_0927-011127.log`，那轮 loadavg 28.40、机器上 14 个 java 进程），
红的是**已经在用 `freePort()` 的那个类**：

```
[ERROR] Tests run: 4, Failures: 0, Errors: 1 -- in com.zifang.z.mq.integration.TopicConfigRestartE2ETest
java.net.BindException: Address already in use
	at sun.nio.ch.Net.bind0(Native Method) ... io.netty.channel.AbstractChannel.bind(...)
```

原因在量具自己身上（`TopicConfigRestartE2ETest:366-373`）：

```java
private static int freePort() throws Exception {
    ServerSocket probe = new ServerSocket(0);
    try { return probe.getLocalPort(); } finally { probe.close(); }   ← 探到就放手
}
```

**探到号 → 立刻 close → 再拿这个号去 bind**，中间那个窗口里谁都可能把号拿走。所以这条不是"改完就干净"，
改完剩下的红会变成这一类。修法两选一（都要在 W4 里定）：
1. **占住不放**：把探测用的 `ServerSocket` 留着（返回对象而不是端口号），等真监听起来之后再关；
2. **绑不上就换号重试**：`bind` 失败 ⇒ 重新取号，重试 N 次再判红（这条会引入循环，判据仍要落在"最终起没起来"）。

顺带一条归因纪律：这一格红**不能记成代码回归**，也不能记成"环境噪音忽略"——它是量具的已知窗口，
读数上要和"写死端口被人抢"分开列（前者换了 `freePort()` 仍会发生，后者不会）。

## ⚠ 01:16–01:39 那 12 轮 250 全量里的 4 格红，已经归因到具体端口：`39876`（本类自己的 Namesrv 口）

上面那条"写死端口被人抢"以前只是**推断**，这一轮量到了是哪一口、以及**为什么我上一轮的洗白是错的**。

```
$ # 每轮在 HAServiceTest 窗口里数"真听起来几个口"（NettyRemotingServer.java:157 的 INFO）
$ python3 逐轮提取 ~/.cache/zmq_waves/dlqfix_250_r{1..12}_0927-011611.log
r1  RED   binds=(空)      r7  green binds=39876,31911
r2  RED   binds=(空)      r8  green binds=39876,31911
r3  green binds=39876,31911   r9  green binds=39876,31911
r4  green binds=39876,31911   r10 RED   binds=(空)
r5  green binds=39876,31911   r11 RED   binds=(空)
r6  green binds=39876,31911   r12 green binds=39876,31911
⇒ 4/4 红轮里**一个口都没起来**，而 `startCluster()` 的第一次 bind 就是 `NAMESRV_PORT=39876`
  （`HAServiceTest:50`）⇒ 红的是**第一个** bind，Broker 的 31911 根本没轮到。
  绿轮 8/8 都是两口齐全 ⇒ 这不是"某一口长期被人占"，是抢号窗口。
```

模块汇总也对得上（不是"少跑了几条断言"，是整类被容器级错误吃掉）：

```
红轮 broker 模块：Tests run: 163, Errors: 1      绿轮 broker 模块：Tests run: 169, Errors: 0
169 - 7 + 1 = 163（HAServiceTest 有 7 条真用例，@BeforeAll 炸 ⇒ 7 条不跑、只留 1 条容器错误）
⇒ 全量总读数是 641（绿）vs 635（红）。
```

**为什么"没人在听这个口"不能洗白它**：`ip_local_port_range = 32768–60999`，而 `39876` 正落在这个区间里
（`31911`、`21911`、`22911`、`29876`、`19876`、`11911` 都在区间外）。落在区间里的意思是
**内核可以把 39876 发给任意一条外出连接当源端口**，而 `ip_local_reserved_ports` 是空的，没有任何保留保护。
我上一轮用 `ss -ltn` 查"有没有人在听 39876"，答案是"没有"，就据此判"不是外来监听者" ——
**那把尺结构上看不到真凶**：抢号的是一条 ESTABLISHED 的**外出** socket，它从来不在 `-l`（listening）那张表里。
250 上现做的阳性对照（一次性的 python，跑完即删，不留进程）：

```
probe: outbound socket holds :39876 (no listen() ever called)
  ss -ltn :39876 -> []                                ← 我上一轮量的就是这一行，它说"干净"
  ss -tan :39876 -> ['ESTAB ... 127.0.0.1:39876  127.0.0.1:22']   ← 真相在这一行
  RESULT: server bind FAILED -> [Errno 98] Address already in use   ← 和红的 errno 同类
after release, server bind: SUCCEEDS
ip_local_port_range: 32768	60999 | ip_local_reserved_ports: ''
```

⇒ **"一条从没 listen 过的外出 socket 就能让 listen bind 报 Address already in use"是实测出来的，不是推的。**

归属不变（还是 W4），但判据要加一条硬约束，否则改完仍会红：
**换成 `freePort()` 只能救 `31911`/`21911` 这类区间外写死号；对 `39876` 这种落在
`ip_local_port_range` 里的号，写死与不写死都会撞**（写死撞外出 socket，不写死撞上面那个 TOCTOU 窗口）。
所以修法必须含"绑不上就换号重试"那一支（上面第 2 案），单靠第 1 案"占住不放"挡不住随机抢号。

顺带订正我在这格里的用词纪律：以后在这份文档里判"端口冲突的来源"，只许同时量 `ss -ltn` **和** `ss -tan sport = :PORT`
两张表并贴出来 —— 一张表的空读数不结论。
