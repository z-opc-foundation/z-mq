这不是"洁癖"，是一条**静默**的错版本装配：本仓 `project.version` 今天正好等于 `1.2.1`，

### 3. 为什么它在别的机器上也不会"当场炸"给我看

⇒ 1.2.1 是**真发布件**：一台干净 CI 机上这些坐标都能从 Central 拉到，所以错装配不会以"依赖缺失"
的形式暴露，只会以"测的是 1.2.1 的行为"的形式暴露。

### 4. 收口判据（写进 W4 的验收，不许用"能构建"当验收）

1. 12 处字面量全部改成 `${project.version}`（或直接删掉 `<version>` 让 dependencyManagement 生效）；
   判据尺：`grep -rn '>1\.2\.1<\|>1\.3\.0<' --include='pom.xml' z-mq-*/pom.xml | grep -v '<parent>' -A1 | wc -l` → 0，
   **并配正对照**：`grep -c 'project.version' pom.xml` 必须 ≥ 8（证明管理段还在、不是我把它删了）。
2. 抬版本后跑 `mvn -o dependency:tree` 全 reactor，**任何**一行 `yuku123:z-mq-*:jar:<非当前版本>` 都判不通过；
   这条是探针树那次的正式版（那次是我做的，读数如上）。
3. 顺带一条同一次运行里白捡的：parent `com.zifang:z-opc:1.0.0-SNAPSHOT`（装在 `~/.m2`）自己的
   dependencyManagement 里 `z-mq-nameserver` 出现两次、版本 `1.2.0` 与 `1.0.2` 打架
   （Maven 原文 WARNING：`must be unique: io.github.yuku123:z-mq-nameserver:jar -> version 1.2.0 vs 1.0.2
   @ .../z-opc-1.0.0-SNAPSHOT.pom, line 688`）。z-mq 抬版本时若去动 parent，要先解掉这一条。
