## 三个没证的子问题（每条先答"用什么尺量"，别直接改代码）

1. **`err=null` 是什么异常？** 现在的出口只打 `e.getMessage()`，**类型丢了**（`DefaultMQPushConsumer` 的 catch 分支：
   `main = 903f8a2` 上实测 `:347` 是 `catch (Exception e)`、`:348` bump 计数、`:349-350` 那条 `log.warn`，
   行号随改动会漂，复跑 `awk 'NR>=342 && NR<=352 {printf "%d\t%s\n", NR,$0}' z-mq-client/src/main/java/com/zifang/z/mq/client/consumer/DefaultMQPushConsumer.java`）。
   分开候选只要一行 src/main：把 `e.getClass().getName()`（或 `e` 本身）交给 logger。
   ⇒ 下一支第一件事就是这一行，否则后面全是猜。
2. **为什么偏偏是"这一个队列的这一次提交"？** 两处形状不同：
   `TxMessageTopic` 是 **1 队列 1 broker**（`TransactionMessageE2ETest:431-432` 写死 `readQueueNums/writeQueueNums=1`）却仍失败一次；
   `IT_PUSH_TOPIC…` 是 **4 队列**（`ZmqE2ETest:389-390`）而只有 `queueId=3` 失败一次。
   ⇒ "整台 broker 地址死了"解释不了"4 个队列只死 1 个"，"队列路由本身缺失"也解释不了"1 队列 1 broker 还死"。
   **两个假设我都分不开**，分它们的尺：把 `brokerAddr` 一起打进那条 WARN + 用 `ConsumerOffsetManager.queryOffset(topic, queueId, group)`
   逐队列对账（W2h 的 `PushOffsetCommitE2ETest` 里已有现成的 `brokerOffset(...)` 读法可以照抄）。
3. **`noroute-group`（topic 从没注册过）在摘边那一跑失败 16 次，但在基线里一条告警都没有 ⇒ 那一路的提交"不抛"。**
   **不抛 ≠ 存住了**：它可能落到某台 broker 的 offset 表里，也可能根本没落。W2h 报告 §5.7 明确记了"没证"。
   这一条与 `feature008`（失败批次整批判提交）、`feature006`（DLQ topic 没注册）是同族：**没注册的 topic 上写位点会发生什么**，全仓零用例。

## 与 W2h 已交付物的边界（别把这一格当成已经修好了）

W2h 交的是**出口 + 读者 + 守卫**：`offsetCommitFailures` 计数器（`AtomicLong`，catch 分支里 bump）、
`PushOffsetCommitE2ETest` 4 例（含"提交被拒 ⇒ ①计数从 0 变正 ②拉取循环没断 ③broker 侧那位没前进"三合一）、
`ConsumerOffsetWiringGuardTest` 5→7 条（结构断言：catch 里不许只有 log；计数必须就是 getter 读的那个字段；出口在 `src/main` 里零业务读者但在测试树里必须有读者）。
⇒ **上面这 2 条既有失败今天仍然没人断**：计数器只在**各自那个消费者实例**上，别的测试的失败不会进到本票用例读的那个计数器里，
而且"运维面读不到这个数"（`z-mq-tools`/admin 零聚合点）也是 W2h §5.5 记下的缺口。
